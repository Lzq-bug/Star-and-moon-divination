## 1. 项目概述

### 1.1 一句话定位

> **"AI 驱动的 Web3 塔罗占卜平台 — 让每一次抽卡都是一次链上奇遇。"**

### 1.2 项目简介

塔罗占卜大师是一个融合 **AI 大模型 + Web3 区块链技术** 的交互式塔罗牌占卜平台。用户连接钱包后，通过抽卡获取 3 张塔罗牌，AI 基于牌面位置、牌义及用户提问生成个性化深度解析，同时提供情绪价值与行动指引。

### 1.3 核心亮点

| 维度 | 亮点 |
|------|------|
| **AI 深度解析** | 基于大模型（如 DeepSeek / Claude），结合塔罗牌义库 + 用户场景，生成有温度、有共情的解读 |
| **链上抽卡可验证** | 每轮抽卡的牌序、时间戳上链，保证"公平抽卡"不可篡改 |
| **NFT 卡牌收藏** | 每张塔罗牌均可作为 NFT 铸造收藏，稀有度分层，支持二级交易 |
| **情绪价值设计** | 解析文案融入心理暗示、正向激励、仪式感交互，不止占卜更是疗愈 |
| **极简美学 UI** | 神秘学视觉风格 + 流畅动效，沉浸式体验 |

### 1.4 一句话打动评委

> *"让千年塔罗智慧遇见 AI 与区块链 — 每一次抽卡都独一无二、不可篡改、充满情感共鸣。"*

### 2.2 行业趋势

- **AI + 玄学热潮：** TikTok / 小红书上的 AI 塔罗、AI 算命内容流量爆炸
- **Web3 社交复苏：** 2026 年市场回暖，用户不再只关注 DeFi，开始追求文化/娱乐类 DApp
- **情绪消费升级：** Z 世代为"情绪价值"付费意愿强 — 占卜、心理测试、冥想类产品增长迅速
- **NFT 应用转型：** 从 PFP 头像转向功能性、互动性 NFT

### 2.3 竞品分析

| 竞品 | 类型 | AI | Web3 | 情绪价值 | 劣势 |
|------|------|:--:|:----:|:--------:|------|

2. **链上抽卡公平性证明** — 传统 App 无法保证"洗牌随机"，我们可以
3. **边占卜边收藏** — 用户既有功能性价值（解读），又有资产性价值（NFT）
4. **可组合性** — 未来可接入其他 Web3 生态（社交平台、元宇宙空间）

## 3. 用户画像与痛点

### 3.1 核心用户画像

#### 👤 用户 A：玄学少女
- **年龄：** 18-28 岁女性
- **特征：** 活跃于小红书/抖音，关注星座、塔罗、MBTI
- **痛点：** 传统占卜太贵（100-500 元/次），找 AI 占卜又觉得没仪式感
- **需求：** 免费/低价的占卜体验 + 好看的卡片分享到朋友圈

#### 👤 用户 B：Web3 探索者
- **年龄：** 22-35 岁，偏男性
- **特征：** 持有加密资产，玩过 NFT、DeFi
- **痛点：** Web3 圈缺少有文化内涵的消费品类 DApp
- **需求：** 可验证公平性的链上应用 + NFT 收藏价值

#### 👤 用户 C：情绪疗愈需求者
- **年龄：** 20-35 岁，男女均可
- **特征：** 近期迷茫、焦虑，寻求心理指引
- **痛点：** 心理咨询门槛高、怕被评判；找朋友聊又怕打扰
- **需求：** 匿名、无评判、有温度的情感陪伴式解读

### 3.2 用户痛点总结

| 痛点 | 我们的解法 |
|------|-----------|
| 传统占卜太贵不透明 | AI 免费/微付费 + 链上可验证 |
| AI 占卜太冰冷没仪式感 | 沉浸式 UI + 有温度的大模型 Prompt 工程 |
| 占卜结果无法保存分享 | NFT 化 + 精美卡片分享图 |
| Web3 DApp 缺乏文化内涵 | 塔罗文化 + AI 解读 + 情绪共鸣 |
| 抽卡公平性存疑 | 链上随机数可验证 |

### 5.2 详细功能描述

#### 5.2.1 钱包连接

| 功能 | 描述 |
|------|------|
| 连接方式 | MetaMask 扫码、OKX Wallet、WalletConnect、EIP-6963 |
| 免 Gas | 使用 ERC-4337 账户抽象，首次交互免 Gas |
| 登录体验 | 连接即登录，无需邮箱/手机号 |
| 链上身份 | 记录用户抽卡次数、收藏数作为链上声誉 |

#### 5.2.2 抽卡流程

```
1. 用户进入"占卜"页面
2. 选择占卜主题：事业 | 爱情 | 财运 | 健康 | 综合
3. 输入内心问题（可选，增强 AI 解读针对性）
4. 点击"开始占卜"
5. 🎬 3D 洗牌动画（约 3 秒）
6. 用户点击"停牌"瞬间——触发生成链上随机数
7. 揭示 3 张卡牌（过去-现在-未来）
8. AI 加载解读...
9. 展示完整解读报告
```

#### 5.2.3 牌阵设计（MVP）

| 位置 | 含义 | 占比 |
|------|------|------|
| **第 1 张：过去** | 影响当前状况的过往因素 | 30% |
| **第 2 张：现在** | 当下的能量与处境 | 40% |
| **第 3 张：未来** | 趋势与可能性指引 | 30% |

> *后续版本可扩展：凯尔特十字、爱情二选一、时间之箭等牌阵*

#### 5.2.4 AI 解读模块

**AI 角色的设定：**

> *"你是塔罗占卜大师——一位温柔、睿智且富有灵性的塔罗导师。你精通 78 张塔罗牌的符号学含义，擅长将古老的智慧与现代人的生活困境结合，给出既有深度又有温度的建议。你的语言细腻、富有诗意，但不说空泛的套话；你会共情，但不过度煽情；你给出指引，但不替用户做决定。"*

**解读结构：**

| 部分 | 内容 | 字数 | 风格 |
|------|------|:----:|------|
| 🌟 总览 | 三张牌整体能量概括 | 80-120 | 诗意+共情 |
| 📜 单牌解析 ×3 | 每张牌正/逆位含义 + 对应位置解读 | 100-150/张 | 专业 + 易懂 |
| 🔗 联动解读 | 三张牌之间的能量关联与叙事线 | 120-200 | 故事感 |
| 💡 建议 | 1-3 条可操作的行动指引 | 60-100 | 落地实用 |
| 💝 情绪寄语 | 一句温暖的收尾 | 20-40 | 治愈 |

**支持的占卜主题：**

| 主题 | 解读侧重点 |
|------|-----------|
| 💼 事业 | 职场困境、跳槽决策、创业方向 |
| ❤️ 爱情 | 感情状态、复合可能、桃花运势 |
| 💰 财运 | 投资时机、财务规划、偏财运 |
| 🏥 健康 | 身心状态、压力管理、养生指引 |
| 🌈 综合 | 全面能量扫描 |

### 5.3 情绪价值设计要点

> 情绪价值是本项目的灵魂，以下是具体设计：

1. **仪式感构建：**
   - 打开 App 的启动星空动画
   - 抽卡时的"屏息时刻"（短暂的加载等待 + 音效）
   - 翻牌动画（卡片正面朝下 → 慢慢翻转揭示）
   - 蜡烛/星光粒子特效

2. **共情式文案：**
   - AI 不要机械输出"这张牌代表..."，而是先共情：
   - *"我看到你现在正处在一个人生的十字路口，这种迷茫我完全理解... 来看看塔罗想对你说什么。"*

3. **正向收尾：**
   - 每条解读以积极的行动指引结束
   - *"星星牌出现在未来位置——宇宙在告诉你，希望就在转角。保持你内心的光。"*

4. **视觉仪式感：**
   - 深色背景 + 微光效
   - 每张卡牌显示星座符号、行星对应等神秘学元素
   - 字体选用优雅衬线体

5. **分享即传递：**
   - 生成的分享卡片带有"能量传递"设计
   - 好友扫码可"接续能量"获得一次免费抽卡

## 6. Web3 集成方案

### 6.1 链的选择

| 选项 | 理由 |
|------|------|
| **Polygon (推荐 MVP)** | Gas 低、速度快、兼容 EVM、OpenSea 支持好 |
| **opBNB / Base** | 备选，同样低 Gas |
| **以太坊主网** | 正式版可跨链桥接，MVP 阶段不用 |

### 6.2 智能合约架构

```
Contracts/
├── TarotCardNFT.sol          # 塔罗牌 NFT 合约（ERC-721）
│   ├── mintReading()         # 铸造单次占卜记录
│   ├── getCardRarity()       # 卡牌稀有度判定
│   └── getReadingHistory()   # 查询用户的占卜历史
│
├── TarotRandomness.sol       # 链上随机数（VFR）
│   ├── requestRandomness()   # 请求 Chainlink VRF
│   └── fulfillRandomness()   # 接收随机数用于抽卡
│
└── TarotToken.sol (V2)       # 平台代币（可选）
    └── 用于支付抽卡费用 / 治理投票
```

### 6.3 抽卡公平性机制

```
用户点击"停牌"
    ↓
前端请求 Chainlink VRF（可验证随机函数）
    ↓
VRF 返回 3 个随机数 → 对应 78 张牌（大阿卡纳 22 张 + 小阿卡纳 56 张）
    ↓
随机数决定：(1) 哪三张牌 (2) 正位/逆位 (3) 展示顺序
    ↓
结果上链存证（event log）
    ↓
用户可随时在区块浏览器上验证本次抽卡结果
```

### 6.4 NFT 卡牌设计

| 属性 | 描述 |
|------|------|
| **标准** | ERC-721 |
| **元数据** | 链上 SVG（图片） + IPFS（解读 JSON） |
| **稀有度** | 按抽到的牌组合判定 |
| 普通 (Common) | 任意 3 张小阿卡纳 | 60% |
| 稀有 (Rare) | 含 1 张大阿卡纳 | 30% |
| 史诗 (Epic) | 含 2 张大阿卡纳 | 8% |
| 传说 (Legendary) | 3 张大阿卡纳 / 特定组合（如"命运三女神"） | 2% |
| **交易** | OpenSea 二级市场 + 版税 5% |

### 6.5 账户抽象（AA）

使用 ERC-4337 实现：
- 新用户无需 Gas 即可进行首次抽卡
- 支持社交恢复（Social Recovery）
- 批量交易（一次签名完成抽卡 + Mint）

## 7. AI 技术架构

### 7.1 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| **大模型** | DeepSeek / Claude API | 中文理解强，成本可控 |
| **RAG 知识库** | 塔罗牌义向量数据库 | 保证 AI 输出准确性 |
| **Prompt 框架** | 结构化 Prompt + Few-shot | 控制输出格式与质量 |
| **流式输出** | SSE (Server-Sent Events) | 实时展示解读过程，提升感知速度 |
| **缓存** | Redis | 常见问题缓存，节省 API 成本 |

### 7.2 RAG 知识库结构

```
知识库 /
├── 大阿卡纳 (22 张) /
│   ├── 0-愚人.json    # 含义、符号学、正/逆位
│   ├── 1-魔术师.json
│   └── ...
│
├── 小阿卡纳 (56 张) /
│   ├── 权杖 (Wands) /   # 火元素 — 行动、激情
│   ├── 圣杯 (Cups) /    # 水元素 — 情感、直觉
│   ├── 宝剑 (Swords) /  # 风元素 — 思维、挑战
│   └── 星币 (Pentacles) # 土元素 — 物质、事业
│
├── 牌阵知识 /
│   └── 三张牌阵.json
│
└── 仪式感语录 /           # 情绪价值语料库
    ├── 开场白.json
    ├── 收尾语.json
    └── 共情话术.json
```

└─────────────────────────────────────────────────────────────┘

### 9.2 详细技术选型

| 层级 | 技术 | 版本/方案 | 选型理由 |
|------|------|:---------:|----------|
| **框架** | Next.js | 14+ | SSR/SSG 支持，SEO 友好，API Routes 一体化 |
| **语言** | TypeScript | 5.x | 类型安全，团队协作友好 |
| **样式** | TailwindCSS | 3.x | 快速开发，设计系统一致性 |
| **动效** | Framer Motion | 11.x | React 动效库首选，支持布局动画 |
| **3D** | Three.js / React Three Fiber | 最新 | 洗牌 3D 动画，沉浸感 |
| **Web3 交互** | wagmi + viem | 最新 | 最流行的 React Web3 框架 |
| **钱包连接** | ConnectKit / RainbowKit | 最新 | 开箱即用的钱包 UI |
| **智能合约** | Solidity + Hardhat | 0.8.x | 以太坊生态标准 |
| **随机数** | Chainlink VRF | v2 | 可验证链上随机数 |
| **AI** | DeepSeek API 或 Claude API | - | 根据成本和效果选择 |
| **向量库** | PGVector 或 Pinecone | - | 塔罗牌义 RAG 检索 |
| **数据库** | PostgreSQL + Prisma | 最新 | 关系型数据存储 |
| **缓存** | Redis / Upstash | - | 会话缓存 + 限流 |

## 12. 风险分析与对策

### 12.1 风险矩阵

| 风险 | 概率 | 影响 | 对策 |
|:----|:----:|:----:|------|
| **AI 解读不准确** | 中 | 高 | RAG 知识库约束 + 人工标注优化 Prompt |
| **链上 Gas 过高** | 低 | 中 | 选择 Polygon L2，Optimistic Rollup |
| **用户对 Web3 门槛畏惧** | 高 | 中 | 账户抽象免 Gas + 渐进式引导 |
| **合规风险（玄学）** | 低 | 高 | 标注"仅供娱乐参考"，不涉及医疗/投资建议 |
| **AI API 成本超支** | 中 | 中 | Redis 缓存 + 限流 + 多模型 fallback |
| **黑客松时间不足** | 高 | 高 | 提前准备好组件库 + 专注核心功能 MVP |

### 12.2 合规说明

- 产品页面必须标注：**"仅供娱乐参考，不构成专业建议"**
- 不涉及医疗诊断、投资理财建议
- 用户数据隐私保护（不上传敏感个人信息）
- NFT 明确为"数字收藏品"，非证券

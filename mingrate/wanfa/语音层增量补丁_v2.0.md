## 7.5 双模交互架构与语音陪伴层

### 7.5.1 设计哲学：两种模式互补不替代

| 模态 | 名称 | 感官主导 | 负责时段 | 情绪曲线 |
|:----:|------|---------|---------|---------|
| 🎴 | **仪式模式** (Ritual Mode) | 视觉 | 抽卡→翻牌→解读展示 | 悬念↗高潮↘回落 |
| 🎙️ | **陪伴模式** (Companion Mode) | 听觉 | 解读完成后→多轮追问→日常陪伴 | 平缓延伸↗温暖收束 |

**核心铁律：** 仪式模式负责"高潮与停顿"，陪伴模式负责"延伸与追问"。
- 翻牌瞬间 🎴 视觉独占，🎙️ 静默。
- 解读完成后的追问场景 🎙️ 接力，🎴 退为背景。
- 任何时候用户点按语音按钮，🎙️ 可临时抢占，🎴 自动降低亮度与音量避免干扰。

### 7.5.2 模态状态机

```
                    ┌─────────────────────────────────────┐
                    │           🎴 仪式模式 (默认)          │
                    │  首页/选主题/切牌/洗牌/停牌/翻牌/解读   │
                    └─────────────────────────────────────┘
                               │              ▲
          解读完成 或 用户点按语音按钮    ┌─────┴──────┐
                               ▼         │ "再来一次"  │
                    ┌─────────────────────┴──── ────┐
                    │      🎙️ 陪伴模式                │
                    │  语音追问 / 深度解读 / 闲聊陪伴   │
                    │  【ASR 唤醒态】                   │
                    └──────────────────────────────── ┘
                               │              ▲
                        用户说出 "再抽一次"    └── "再抽一次"
                         或点按"再来一次"          语音触发
                               ▼
                    ┌─────────────────────────────────────┐
                    │           回到 🎴 仪式模式            │
                    │        重置到选主题 / 直接洗牌         │
                    └─────────────────────────────────────┘
```

**切换触发条件详表：**

| 方向 | 触发条件 | 过渡动效 | 耗时 |
|:----|---------|---------|:----:|
| 🎴→🎙️ | 解读流式输出完成（自动） | 解读区底部平滑浮现语音按钮 + 微光脉动 | 300ms |
| 🎴→🎙️ | 用户点击悬浮语音按钮（任意时刻） | 画面降低 30% 亮度，语音波形出现在屏幕下方 | 400ms |
| 🎙️→🎴 | 用户点击「再来一次」 | 语音波形缩回按钮 → 画面亮度恢复 | 200ms |
| 🎙️→🎴 | 用户说出"再抽一次"（需要通过 NLU 识别） | 语音回合结束后自动切换 | 500ms |
| 🎴→🎴 | 同模态内正常流程推进 | — | 按节点时间 |

### 7.5.3 双模冲突解决原则

| 冲突场景 | 原则 | 具体做法 |
|---------|------|---------|
| 翻牌时语音仍在播放上一句 | **视觉优先** | 立即停止 TTS，静音，执行翻牌动效 |
| 语音朗读时用户点按暂停 | **用户优先** | 随时可打断，打断后画面停留在当前段 |
| 用户语音提问但 ASR 超时 | **降级到文字** | 显示"我没听清…"文案，同时显示文字输入框作为 fallback |
| 解读长文本 > 30s | **分块朗读** | 每张牌作为一个 TTS 分块，段间留 0.5s 停顿 |

### 朗读与打字机同步策略（关键设计）

> 解决"语音读得快 vs 文字打字机慢"的范式冲突。

**方案：分阶段切换速度**

| 阶段 | 语音行为 | 打字机行为 | 速度差处理 |
|:----|---------|-----------|-----------|
| **总览段**（篇幅 80-120 字） | 语音以正常语速朗读（≈250字/min） | 打字机以 30ms/字 输出（≈120字/min） | **语音领读**，打字机落后 2-3s 追赶，用户听到的比看到的多→产生"信息补全"满足感 |
| **单牌解析×3**（每段 100-150 字） | 语音朗读 + 段间 0.5s 停顿 | 打字机正常输出 | **同步为主**，语音读到关键词时文字刚好出现，利用听觉强化视觉记忆 |
| **联动解读**（120-200 字） | 语音语速放慢至 200字/min，增加叙事感 | 打字机同速 | **刻意慢读**与打字机同步，营造"故事时间"感 |
| **建议×3**（每段 20-40 字） | 语音逐条朗读，条间 1s 停顿 | 打字机一次性显示该条 | **语音节奏控制**——停顿时用户默读，强化记忆 |
| **寄语**（20-40 字） | 语音语速最慢（160字/min），音色更温暖 | 打字机跟随 | **刻意拉长**，让用户感受最后一句话的情绪重量 |

**技术实现：** 后端输出 JSON 时，每一块内容携带 `speed_marker` 字段（`normal` / `slow` / `pause_between`），前端 TTS 调用时据此调节语速参数。

## 7.5.5 语音交互层详细设计

### 7.5.5.1 语音按钮设计

| 维度 | 设计 |
|------|------|
| **位置** | 屏幕右下角悬浮（`position: fixed; bottom: 100px; right: 20px; z-index: 30`） |
| **静态态** | 半透明紫色圆形按钮（直径 48px），中心一个麦克风图标 🎤 |
| **可说话态** | 按钮放大至 56px，外围金色光环脉动（`box-shadow`呼吸动画），微文字提示 `"我听着呢"` 浮现在按钮上方 |
| **录音态** | 按钮转为红色，波形动画（CSS 3 条竖线振幅变化模拟收音） |
| **朗读态** | 按钮转为声波纹（环形扩散动画），点击可打断 |
| **出现时机** | 进入占卜页后一直存在，但不同状态有不同"显眼度" |

**高亮提示时机（用户最可能想说话的时机）：**
1. 解读完成时 → 脉冲 3s 吸引注意
2. ASR 检测到用户沉默 > 5s → 从隐 → 显
3. 用户刚听完一段牌意 → 短暂高亮 1s "想聊聊吗？"

### 7.5.5.2 对话循环链路（半双工）

```
[用户] 按住语音按钮 → 开始说话
    ↓
[ASR] 浏览器 SpeechRecognition / 阿里云语音识别
    ↓ 识别文本: "能再讲讲死神牌吗？"
[LLM] 注入当前上下文（牌面 + 对话历史 + 用户主题）
    ↓ 生成回复（遵循原有 JSON schema，但更口语化）
[TTS] 阿里云百炼「龙嫱」voice_id = "longqiang"
    ↓ 流式播放音频
[用户] 可随时按按钮打断 → 进入下一轮
    ↓
[降级] 如果 ASR 超时 / 识别置信度 < 0.6
    → 显示"我没太听清，可以打字告诉我吗？"
    → 同时弹出文字输入框
```

### 7.5.5.3 唤醒与问候文案

| 时机 | 主动唤起文案 | 优先级 |

### 7.5.5.4 语音场景下的多轮追问设计

区别于文字追问气泡（「深入分析」「更多建议」），语音场景的追问靠话术引导：

```
🎙️ 占卜师："关于刚才这张【战车】牌，你想了解——
    ➤ 它在事业上的含义……   [停顿2s，给用户插话空间]
    ➤ 还是它和上一张牌的联系？
    直接告诉我。"
```

**引导话术结构：**
- **大门式：** "你想深入聊感情，还是事业？" → 用户回答"感情" → LLM 针对性展开
- **漏斗式：** "刚才说到【隐士】牌，它的核心是内省。你最近有在独处思考什么吗？" → 用户可自由回答（更自然但更难 NLU）
- **确认式：** "我建议你记录一周情绪日记。这个建议对你有帮助吗？" → 用户确认/否定 → 追问"那什么样的建议更适合你？"

🟢 **MVP 采用大门式**（对 ASR 识别要求最低），🟡 **V2 增加漏斗式**（需 NLU 主题分类）。

### 7.5.5.5 静默与降级兜底

| 异常场景 | 语音话术 | 备用方案 |
|---------|---------|---------|
| ASR 无识别结果（3s 超时） | `"我没听到声音呢，是还在想怎么问吗？不着急。"` | 显示文字输入框+回车发送 |
| ASR 置信度低（< 0.6） | `"我好像没太听清，能再说一遍吗？"` | 重试 2 次后降级到文字 |
| TTS 播放失败（网络/API） | — | 静默降级，直接显示文字，不打断感受 |
| LLM 响应超时（> 5s） | `"嗯……星盘在运转，稍等一下。"` | 显示文字 loading，语音用轻音乐填补空白 |
| 用户连续 2 次打断 | `"看起来你比较着急。我们打字聊吧？"` | 自动切换到文字输入模式 |

## 9.1.b 语音层技术组件（增量）

| 层级 | 组件 | MVP/48h 方案 | 正式方案 | 选型理由 |
|:----|:----|:------------:|:--------:|---------|
| **ASR** | 语音识别 | 🟢 **Web Speech API**（`SpeechRecognition`）——免费，内置于 Chrome，无需 API Key | 阿里云智能语音交互 | MVP 0 成本，浏览器原生支持中文 |
| **LLM** | 对话生成 | 同原有 DeepSeek/Claude API，追加语音上下文 prompt | 同左 | 复用已有设施，不新增模型 |
| **TTS** | 语音合成 | 🟢 **阿里云百炼「龙嫱」**（voice_id: `longqiang`）——免费额度内 | 🟡 微软 Azure TTS（情感更丰富） | 阿里云百炼新用户赠送百万字符，中文女声温暖，适配塔罗场景 |
| **VAD** | 语音活动检测 | 🟢 **浏览器原生 + 按钮起停**（半双工无需 VAD） | 全双工 VAD（Silero VAD） | 半双工方案免除 VAD 复杂度 |
| **WebSocket** | 流式通信 | 同原有 SSE（用于 LLM 流式输出 + TTS 分块推送） | 同左 | 复用现有 SSE 通道 |

### 半双工方案说明（为什么 48h 不做全双工）

| 维度 | 半双工 ✅ | 全双工 ❌ |
|:----|:--------:|:---------:|
| **实现复杂度** | 按钮起停，一轮一轮对话 | 需要 VAD 实时检测、打断逻辑、双工 stream 管理 |
| **ASR 要求** | 用户说完再识别，延迟可以 1-2s | 需要实时流式 ASR，每 200ms 返回一个 fragment |
| **TTS 要求** | 播放完整句子，可整句打断 | 需要 chunk 级实时合成和流式回放 |
| **MVP 可行性** | **48h 可跑通** | 至少需要 2 周专门开发 |
| **用户体验** | 够用——"按住说话→听回答→再说话" | 更自然但边际收益递减 |

**数据流架构（伪代码）：**

```python
# 半双工语音对话循环
class VoiceSession:
    def __init__(self, reading_context):
        self.context = reading_context  # 三张牌 + 主题 + 对话历史
        self.history = []
    
    def handle_user_speech(self, audio_input):
        # 1. ASR
        text = asr.recognize(audio_input)  # Web Speech API / 阿里云
        if not text or confidence < 0.6:
            return fallback_to_text()
        
        # 2. 注入上下文
        messages = self.build_prompt(text)
        
        # 3. LLM 生成（流式）
        response_text = ""
        for chunk in llm.stream(messages):   # 沿用原有 SSE
            response_text += chunk
            # 分句缓存，满一句就送 TTS
            if is_complete_sentence(chunk):
                tts.speak(chunk, voice_id="longqiang")
        
        # 4. 更新历史
        self.history.append({"role": "user", "content": text})
        self.history.append({"role": "assistant", "content": response_text})
    
    def build_prompt(self, user_text):
        return [
            {"role": "system", "content": self.VOICE_SYSTEM_PROMPT},
            {"role": "user", "content": f"语音对话场景。当前用户问：{user_text}" +
             f"\n上下文：本轮占卜主题={self.context.theme}，牌面={self.context.cards}" +
             f"\n对话历史={self.history[-4:]}"}  # 最近2轮
        ]
    
    VOICE_SYSTEM_PROMPT = """你现在在语音对话模式下工作。以下约束优先：
1. 回答用口语化的中文，适合朗读，不要用Markdown/JSON格式
2. 每段回答控制在 2-4 句，方便 TTS 朗读不超长
3. 使用第二人称"你"，保持温暖陪伴感
4. 如果用户的问题不在占卜范畴（如问天气/问数学），温柔地引导回到占卜话题
5. 不要重复输出已有牌面信息——用户已经从视觉看到了"""
```

### 单次语音回合预算

| 环节 | 延迟 | token/费用 |
|:----|:----:|:----------:|
| ASR 识别 | 0.5-1.5s（用户说完到返回文本） | 0（Web Speech API 免费） |
| LLM 推理（轻量对话，非完整解读） | 1-2s | 200-400 tokens（约为解读的 1/3） |
| TTS 合成 + 首句播放 | 0.3s 合成 + 即时流式 | 0（阿里云百炼免费额度内） |
| **总延迟** | **1.8-3.8s** | 用户可接受范围内（对话场景 < 4s 算流畅） |

> **总 token 约束保持 800-1200**：语音对话每轮 LLM 输入 200-400t（上下文+历史）+ 输出 200-400t（2-4句回答），远低于完整解读。

## 衔接说明：语音层与原有各层的握手协议

> 本说明单独输出，不插入 PRD，作为技术实现者的沟通文档。

### 1. 语音层 → 抽卡层的握手

```
[抽卡层] 状态变化 → 通知 [语音层]
  事件：STATE_CHANGED
  接口：voiceLayer.onStateChange(newState, payload)
  映射：
    'LANDING'        → 语音按钮隐身
    'THEME_SELECT'   → 语音按钮显示，隐身态
    'SPINNING'       → 语音按钮半透明（可用但不推荐）
    'VRF_WAIT'       → 语音按钮禁用
    'REVEALING'      → 语音按钮禁用，直到翻牌完成
    'READING'        → 语音按钮切换为"朗读态"
    'COMPLETE'       → 语音按钮切换为"可说话态"，高亮脉动
```

### 2. 语音层 → AI 解读层的握手

```
[解读层] 流式输出 → [语音层] 朗读
  数据流：SSE chunk → voiceLayer.appendChunk(text, section_type)
  同步逻辑：
    - 语音领读模式（总览段）：voiceLayer 先开始读，typer 追赶
    - 语音同步模式（单牌段）：voiceLayer 等 typer 显示了牌名后再读
    - 纯视觉模式（翻牌中）：voiceLayer 保持静默

  接口：
    voiceLayer.startReading(sections)   // 开始朗读全篇
    voiceLayer.pause()                  // 翻牌/打断
    voiceLayer.resume()                 // 恢复
    voiceLayer.skip()                   // 跳到下一段
    voiceLayer.stop()                   // 停止朗读，切回静默
```

### 3. 语音层 → 情绪价值层的握手

```
[情绪检测] → [语音层] 调整发声参数
  规则：
    if 检测到 sentimentalTag == 'dark':
        voiceLayer.setTone('softer')     # 音色柔和 +2dB
        voiceLayer.setSpeed(0.8)          # 语速降至 80%
        voiceLayer.autoPrompt = false     # 不自动追问
    if 检测到 sentimentalTag == 'bright':
        voiceLayer.setTone('warm')        # 音色温暖
        voiceLayer.setSpeed(1.0)
        voiceLayer.autoPrompt = true      # 可主动追问
```

### 4. 数据冲突清单

| 冲突项 | 仲裁规则 | 实现位置 |
|:------|---------|---------|
| 语音朗读中用户切牌 | 立即终止 TTS，语音按钮禁用 | `main.ts` 状态机 `onStateChange` |
| TTS 流式播放中翻牌触发 | TTS 暂停 → 翻牌 → 0.5s → 恢复 | `voiceLayer.pause()` → 动画 → `resume()` |
| 背景音乐 vs TTS 人声 | TTS 播放时背景音量自动降 6dB，停止后恢复 | CSS `audio` volume 控制 |
| 语音对话中收到"再来一次"指令 | 清除对话历史，重置语音状态到初始 | `voiceSession.reset()` |
| 同一段文字同时被语音和打字机输出 | 各走各的缓冲区，不共享状态，仅靠时间对齐 | 无共享锁，谁快谁先 |
